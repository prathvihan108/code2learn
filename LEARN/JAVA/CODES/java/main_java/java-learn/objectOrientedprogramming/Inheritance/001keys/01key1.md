# method  overiding

Certainly! Here are some important concepts and considerations related to method overriding in Java:
1. Method Signature:

    The overridden method in the subclass must have the same method signature (name, return type, and parameter types) as the method in the superclass.

2. Access Modifiers:

    The access level (visibility) of the overriding method in the subclass must be the same as or more accessible than the overridden method in the superclass.
    It's valid to override a method with a public method, but not with a private one.

3. Return Type:

    The return type of the overriding method can be the same as or a subtype of the return type of the overridden method.
    Covariant return types were introduced in Java 5, allowing more specific return types in the subclass.

4. @Override Annotation:

    While not required, it's a good practice to use the @Override annotation when you intend to override a method. The compiler checks that the annotated method is indeed an overridden method.

java

@Override
public void overriddenMethod() {
    // ...
}

5. super Keyword:

    Inside the overriding method, you can use the super keyword to call the overridden method in the superclass.

java

@Override
void overriddenMethod() {
    super.overriddenMethod(); // Calls the overridden method in the superclass
    // Additional functionality in the subclass
}

6. final and static Methods:

    final methods cannot be overridden.
    static methods are not overridden; they are hidden in subclasses. The method to be called is determined at compile-time based on the reference type.

7. abstract Methods:

    If a superclass has an abstract method, the subclass must provide a concrete implementation for that method.

8. Constructors:

    Constructors are not overridden but are called implicitly or explicitly in the subclass.

9. Dynamic Method Dispatch:

    Overridden methods are called dynamically at runtime based on the actual object type rather than the reference type.

    You can use the final modifier to prevent a method from being overridden in subclasses.

# Abstract Classes

Certainly! Here are some important points related to abstract classes in Java:
1. Abstract Classes:

    An abstract class is a class that cannot be instantiated on its own.
    It is meant to be subclassed by concrete (non-abstract) classes.
    Abstract classes can contain both abstract and concrete methods.

2. Abstract Methods:

    An abstract method is a method declared without an implementation (no method body).
    Abstract methods are meant to be implemented by concrete subclasses.
    Abstract methods are declared using the abstract keyword.

java

abstract class AbstractClass {
    abstract void abstractMethod();
}

3. Concrete Methods:

    Abstract classes can also have concrete methods with an implementation.
    Concrete methods can be inherited by subclasses but can also be overridden.

java

abstract class AbstractClass {
    abstract void abstractMethod();

    void concreteMethod() {
        System.out.println("Concrete method in AbstractClass");
    }
}

4. Extending Abstract Classes:

    To use an abstract class, you must create a concrete subclass that extends the abstract class.
    The concrete subclass must provide implementations for all abstract methods.

java

class ConcreteClass extends AbstractClass {
    @Override
    void abstractMethod() {
        System.out.println("Implementation of abstractMethod in ConcreteClass");
    }
}

5. Abstract Classes vs. Interfaces:

    Abstract classes can have fields (variables), constructors, and non-abstract methods.
    Interfaces support multiple inheritance, while a class can extend only one abstract class.

6. Constructors in Abstract Classes:

    Abstract classes can have constructors.
    Constructors in abstract classes are used when an object of a concrete subclass is created.

7. Access Modifiers:

    Abstract methods can have access modifiers (public, protected, default, private).
    Abstract classes can have access modifiers for fields, methods, and constructors.

8. Object Class:

    Every class, including abstract classes, is a subclass of the Object class by default.
    Abstract classes inherit methods from the Object class.

9. Final and Abstract:

    Abstract classes can be marked as final, preventing them from being subclassed.
    However, it is uncommon to have a final abstract class since the primary purpose is to be subclassed.

10. Polymorphism:

    Abstract classes can be used in polymorphism, allowing references of the abstract class type to hold objects of its concrete subclasses.

java

AbstractClass obj = new ConcreteClass();
